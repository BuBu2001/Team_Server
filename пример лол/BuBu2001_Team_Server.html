Team Server — единая система Host ⇄ Pi

Локальная система для работы двух машин в одной сети:

  • Host — запускает сервер (основной сайт + консоль-хост), хранит файлы и журнал;
  • Pi — подключается к Host, отправляет файлы и проекты, смотрит диаграммы, отслеживает работу.

Все модули связаны в одну систему: общее хранилище data/files и data/projects, единая БД data/team_server.db (журнал действий виден и в консоли, и на сайте), одни и те же генераторы диаграмм (app_platform) у веб-анализа и консоли.

Основной интерфейс — собственный сайт (React + Vite, тема «Дракон»), который раздаётся по адресу /. Сайт общается с сервером по JSON-API (/api/*). Рядом остались служебные разделы: /site — сайт gitingest со своими API-доками (/site/docs), и /api/cryless — HTTP-API библиотеки команд cryless.

Структура

app_platform/          # сервер: JSON-API + раздача сайта (FastAPI)
                       #   + HTTP-API для CLI cryless (cryless_api.py)
web/                   # основной сайт: React + TS + Vite + Tailwind (тема «Дракон»)
                       #   src/ — исходники, dist/ — собранный сайт (раздаётся сервером)
getting_started/       # консоль Host ⇄ Pi: TCP-протокол, обмен файлами, диаграммы
                       #   + test_mode.py — Host и Pi в одном процессе (./run.sh demo)
gitdiagram-static/     # статический анализ кода → mermaid-диаграмма
cryless/               # библиотека команд cryless (работает как git)
data/                  # общее хранилище (files, projects, exports) + team_server.db
run_server.py          # точка входа сервера

Установка (любой Linux-дистрибутив, обе машины)

Одна команда — дальше скрипт всё сделает сам:

cd Team_Server-main
./setup.sh          # зависимости Python + сборка сайта (web/dist)
./setup.sh --dev    # + pytest и инструменты тестов (нужно один раз для ./run.sh test)
./setup.sh --no-web # не собирать фронтенд (использовать готовый web/dist)
Copy code to clipboard

setup.sh сам определяет дистрибутив и пакетный менеджер (apt, dnf, yum, pacman, zypper, apk, xbps, emerge, eopkg, Termux pkg) и, если чего-то не хватает (python3 ≥ 3.10, python3-venv/pip, git, Node.js/npm), предлагает установить недостающие пакеты — с вашего подтверждения. В систему ничего не ставится без спроса; Python-зависимости идут только в виртуальное окружение .venv, а Node — в локальную папку web/node_modules.

Собранный сайт (web/dist) лежит в репозитории, поэтому если Node нет и собирать не хочется — сервер всё равно отдаст готовую сборку (--no-web).

Запуск

Host — сервер (сайт + хост консоли)

./run.sh            # = ./run.sh server
Copy code to clipboard

Сервер слушает 0.0.0.0:8000. Откройте http://<IP-хоста>:8000 в браузере — это основной сайт Team Server. Вход без пароля, по нику (2–32 символа: латиница, цифры, _ . -); при первом входе аккаунт создаётся автоматически с ролью Pi, а роль Host можно выбрать в «Настройках».

Разделы сайта:

  • Обзор — сводка: проекты, участники, действия за сегодня, последний журнал;
  • Проекты — загрузка (zip-архив или ссылка на репозиторий), карточки проектов, анализ, диаграмма кода, PNG-структура, digest, выгрузка JSON, удаление;
  • Анализ репозитория — разбор любого публичного git-репозитория по ссылке (без сохранения в проекты); для приватных можно указать токен;
  • Журнал — единый журнал действий (веб + консоль), с поиском;
  • Команда — пользователи и роли;
  • Cryless — инструкция и статус сервера для библиотеки команд cryless;
  • Настройки — профиль, смена роли Host/Pi, выход.

Отдельным пунктом меню доступны сайт gitingest (/site) и API-документация (/site/docs).

Для разработки самого сайта (горячая перезагрузка Vite, прокси /api и /site на 127.0.0.1:8000):

./run.sh server     # в одном терминале — сервер
./run.sh dev        # в другом — Vite на http://localhost:5173
Copy code to clipboard

Отдельно запускать консоль-хост не обязательно: сайт и консоль работают на одном сервере и пишут в одну БД и одно хранилище.

Pi (и Host) — консоль обмена файлами

./run.sh console --host <IP-хоста>    # на Pi
./run.sh console                      # на Host (режим выберет в меню)
Copy code to clipboard

Консоль спросит режим (host/pi) и адрес хоста (по умолчанию порт 47823; для Pi — --host <IP-хоста>), далее команды: upload (файл или zip-проект), download, tree, analyze, journal, quit. Загруженные проекты и файлы появляются на сайте Host без дополнительных действий.

Тестовый режим: Host + Pi на одной машине

Обычно нужны две машины (Host и Pi). Чтобы проверить всю систему на одной машине, есть тестовый режим — он совмещает Host и Pi в одном процессе: хост-сервер поднимается в фоне, а роль Pi тут же проходит полный цикл (файл → проект → диаграмма кода → mermaid-дерево → PNG → скачивание → журнал) и печатает отчёт «что проверено» с итогом TEST MODE PASS.

./run.sh demo                        # Host + Pi вместе, на одной машине
./run.sh demo --with-web             # и ещё проверить основной сайт по HTTP
./run.sh demo --test-isolated        # временное хранилище/БД (рабочие не трогает)
./run.sh demo --demo-dir ~/my_project  # отправить свой проект вместо образца
Copy code to clipboard

По умолчанию результаты пишутся в общее хранилище data/, поэтому после теста присланный проект и журнал видно на сайте. Без второй машины ничего настраивать не нужно — всё проверяется одной командой.

Pi — библиотека команд cryless (как git)

Второй, «гитовый» способ отправки проекта: команды запускаются прямо в корне проекта и работают через тот же сервер Host.

cd ~/my_project

cryless create repository my_project   # создать репозиторий (и .cryless/ в проекте)
cryless load data my_project           # загрузить файлы проекта на сервер
cryless connection check               # проверить, есть ли соединение с сервером
cryless help                           # справка по командам
Copy code to clipboard

Через обёртку run.sh то же самое: ./run.sh cryless help, ./run.sh cryless connection check и т. д. При первом запуске не забудьте указать сервер и ник:

cryless create repository my_project --server http://<IP-хоста>:8000 --user vanya_pi
Copy code to clipboard

Условия (проверяются самой библиотекой):

  • команду запускают в корне проекта — там, где лежат его файлы;
  • в имени проекта нет пробелов и нет кириллицы — только латиница, цифры, точка, дефис, подчёркивание (my_project, api-v2, site.ru).

После create repository в проекте появляются .cryless/ (настройки и токен доступа, только для владельца) и .crylessignore — что не отправлять на сервер (синтаксис .gitignore; по умолчанию исключены .venv/, __pycache__/, *.log, .env и т. п.). load data заменяет содержимое репозитория целиком (как git push) и сразу запускает анализ: на сервере появляются PNG-структура, digest и mermaid-диаграмма, а действие попадает в общий журнал.

Переменные окружения (необязательно)

Переменная Назначение
TEAM_SERVER_DB путь к БД (по умолчанию data/team_server.db)
TEAM_SERVER_DATA каталог данных сервера (по умолчанию data/)
GETTINGSTARTED_STORAGE базовый каталог хранения консоли (по умолчанию data/)
CRYLESS_SERVER адрес сервера для cryless (по умолчанию http://localhost:8000)
CRYLESS_USER ник пользователя для cryless
CRYLESS_HOME каталог настроек cryless (по умолчанию ~/.config/cryless)

JSON-API (для сайта и интеграций)

Сайт работает через JSON-API; его же можно использовать напрямую (сессия — cookie nick, как и в браузере).

Метод и путь Назначение
POST /api/auth/login вход/регистрация по нику ({"nick": "..."})
GET /api/auth/me текущий пользователь
POST /api/auth/role смена роли (host / pi)
POST /api/auth/logout выход
GET /api/users пользователи и роли
GET /api/stats сводка (проекты, участники, действия)
GET /api/journal?limit= журнал действий
GET /api/projects список проектов
POST /api/projects загрузка проекта (multipart: name, archive или source)
GET /api/projects/{id} проект + сохранённый анализ
DELETE /api/projects/{id} удаление проекта (владелец или Host)
POST /api/projects/{id}/analyze анализ: структура, digest, диаграмма, PNG
GET /api/projects/{id}/diagram mermaid-диаграмма
GET /api/projects/{id}/digest текстовый digest
GET /api/projects/{id}/png PNG со структурой
GET /api/projects/{id}/export выгрузка данных в JSON
POST /api/ingest разобрать произвольный репозиторий по ссылке

Служебные API: /api/cryless/* (для CLI cryless) и /site/docs (Swagger сайта gitingest). Неизвестные /api/* отвечают честным 404.

Роли

  • Host — видит весь журнал, может анализировать и скачивать материалы любого проекта (PNG/digest/диаграмма/JSON);
  • Pi — видит в журнале только свои действия, работает со своими проектами; чужие материалы недоступны (403).
