# Team Server — единая система Host ⇄ Pi

Локальная система для работы двух машин в одной сети:

- **Host** — запускает сервер (веб-панель + консоль-хост), хранит файлы и журнал;
- **Pi** — подключается к Host, отправляет файлы и проекты, смотрит диаграммы, отслеживает работу.

Все модули связаны в одну систему: общее хранилище `data/files` и `data/projects`,
единая БД `data/team_server.db` (журнал действий виден и в консоли, и в веб-панели),
одни и те же генераторы диаграмм (`app_platform`) у веб-анализа и консоли.

## Структура

```
app_platform/          # веб-панель (FastAPI): загрузка, анализ, диаграммы, журнал, роли
                       #   + HTTP-API для CLI cryless (cryless_api.py)
getting_started/       # консоль Host ⇄ Pi: TCP-протокол, обмен файлами, диаграммы
                       #   + test_mode.py — Host и Pi в одном процессе (./run.sh demo)
gitdiagram-static/     # статический анализ кода → mermaid-диаграмма
cryless/               # библиотека команд cryless (работает как git)
data/                  # общее хранилище (files, projects, exports) + team_server.db
run_server.py          # точка входа веб-сервера
```

## Установка (любой Linux-дистрибутив, обе машины)

Одна команда — дальше скрипт всё сделает сам:

```bash
cd Team_Server-main
./setup.sh          # рабочие зависимости
./setup.sh --dev    # + pytest и инструменты тестов (нужно один раз для ./run.sh test)
```

`setup.sh` сам определяет дистрибутив и пакетный менеджер (apt, dnf, yum,
pacman, zypper, apk, xbps, emerge, eopkg, Termux pkg) и, если чего-то не
хватает (python3 ≥ 3.10, python3-venv/pip, git), предлагает установить
недостающие пакеты — с вашего подтверждения. В систему ничего не ставится
без спроса; Python-зависимости идут только в виртуальное окружение `.venv`.

## Запуск

### Host — сервер (веб-панель + хост консоли)

```bash
./run.sh            # = ./run.sh server
```

Сервер слушает `0.0.0.0:8000`. Откройте `http://<IP-хоста>:8000` в браузере —
это веб-панель: панель проектов, анализ репозитория, журнал действий, сайт gitingest.

Отдельно запускать консоль-хост не обязательно: веб-панель и консоль работают
на одном сервере и пишут в одну БД и одно хранилище.

### Pi (и Host) — консоль обмена файлами

```bash
./run.sh console --host <IP-хоста>    # на Pi
./run.sh console                      # на Host (режим выберет в меню)
```

Консоль спросит режим (`host`/`pi`) и адрес хоста (по умолчанию порт `47823`;
для Pi — `--host <IP-хоста>`), далее команды: `upload` (файл или zip-проект),
`download`, `tree`, `analyze`, `journal`, `quit`. Загруженные проекты и файлы
появляются на веб-панели Host без дополнительных действий.

### Тестовый режим: Host + Pi на одной машине

Обычно нужны две машины (Host и Pi). Чтобы проверить всю систему на одной
машине, есть тестовый режим — он **совмещает Host и Pi в одном процессе**:
хост-сервер поднимается в фоне, а роль Pi тут же проходит полный цикл
(файл → проект → диаграмма кода → mermaid-дерево → PNG → скачивание → журнал)
и печатает отчёт «что проверено» с итогом `TEST MODE PASS`.

```bash
./run.sh demo                        # Host + Pi вместе, на одной машине
./run.sh demo --with-web             # и ещё проверить веб-панель по HTTP
./run.sh demo --test-isolated        # временное хранилище/БД (рабочие не трогает)
./run.sh demo --demo-dir ~/my_project  # отправить свой проект вместо образца
```

По умолчанию результаты пишутся в общее хранилище `data/`, поэтому после теста
присланный проект и журнал видно на веб-панели. Без второй машины ничего
настраивать не нужно — всё проверяется одной командой.

### Pi — библиотека команд `cryless` (как git)

Второй, «гитовый» способ отправки проекта: команды запускаются прямо в корне
проекта и работают через тот же сервер Host.

```bash
cd ~/my_project

cryless create repository my_project   # создать репозиторий (и .cryless/ в проекте)
cryless load data my_project           # загрузить файлы проекта на сервер
cryless connection check               # проверить, есть ли соединение с сервером
cryless help                           # справка по командам
```

Через обёртку `run.sh` то же самое: `./run.sh cryless help`,
`./run.sh cryless connection check` и т. д. При первом запуске не забудьте
указать сервер и ник:

```bash
cryless create repository my_project --server http://<IP-хоста>:8000 --user vanya_pi
```

Условия (проверяются самой библиотекой):

* команду запускают **в корне проекта** — там, где лежат его файлы;
* в имени проекта нет **пробелов** и нет **кириллицы** — только латиница,
  цифры, точка, дефис, подчёркивание (`my_project`, `api-v2`, `site.ru`).

После `create repository` в проекте появляются `.cryless/` (настройки и токен
доступа, только для владельца) и `.crylessignore` — что не отправлять на сервер
(синтаксис `.gitignore`; по умолчанию исключены `.venv/`, `__pycache__/`,
`*.log`, `.env` и т. п.). `load data` заменяет содержимое репозитория целиком
(как `git push`) и сразу запускает анализ: на сервере появляются PNG-структура,
digest и mermaid-диаграмма, а действие попадает в общий журнал.

### Переменные окружения (необязательно)

| Переменная | Назначение |
|---|---|
| `TEAM_SERVER_DB` | путь к БД (по умолчанию `data/team_server.db`) |
| `TEAM_SERVER_DATA` | каталог данных сервера (по умолчанию `data/`) |
| `GETTINGSTARTED_STORAGE` | базовый каталог хранения консоли (по умолчанию `data/`) |
| `CRYLESS_SERVER` | адрес сервера для cryless (по умолчанию `http://localhost:8000`) |
| `CRYLESS_USER` | ник пользователя для cryless |
| `CRYLESS_HOME` | каталог настроек cryless (по умолчанию `~/.config/cryless`) |

## Тесты

```bash
./run.sh test    # e2e связности (16, включая тестовый режим Host+Pi) + веб-панель (6) + cryless (16)
```

Эквиваленты без скриптов:

```bash
.venv/bin/python getting_started/tests/e2e_system.py
.venv/bin/python -m pytest tests/app_platform tests/cryless -q
```

## Роли

- **Host** — видит весь журнал, скачивает чужие экспорты (PNG/digest/API);
- **Pi** — видит в журнале только свои действия, работает со своими проектами.
