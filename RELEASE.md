# Team Server v1.0.0

> Локальная платформа для работы двух машин в одной сети: **Host** выполняет всю
> серверную работу, **Pi** отправляет проекты и получает результаты анализа.
> Основной интерфейс — собственный веб-сайт (тема «Дракон»).

---

## Что это

**Team Server** — самодостаточная система для небольшой команды или учебной
сети. Один компьютер включается как сервер (**Host**), остальные подключаются
как **Pi**. Host хранит файлы, единую базу и журнал, запускает анализ кода
(gitingest + gitdiagram-static), строит диаграммы (mermaid) и PNG-структуру
проекта. Управлять системой можно тремя способами: с веб-сайта, из консоли
Host ⇄ Pi и библиотекой команд `cryless`.

Все интерфейсы — это **одна система**, а не три отдельные программы:

- общее хранилище `data/` (файлы, проекты, экспорты);
- единая БД `data/team_server.db`;
- одни и те же генераторы диаграмм у сайта и консоли;
- действия из консоли, cryless и сайта попадают в **один журнал**.

## Состав проекта

| Каталог | Назначение |
|---|---|
| `web/` | Основной сайт: React 18 + TypeScript + Vite + Tailwind 4. Исходники в `src/`, собранный сайт в `dist/` (раздаётся сервером). |
| `app_platform/` | Сервер (FastAPI): JSON-API `/api/*`, раздача сайта, интеграция gitingest `/site`, HTTP-API cryless `/api/cryless`. |
| `getting_started/` | Консоль Host ⇄ Pi: TCP-протокол, обмен файлами/проектами, тестовый режим на одной машине. |
| `gitdiagram-static/` | Статический анализ кода → mermaid-диаграмма архитектуры. |
| `cryless/` | Библиотека команд `cryless` (работает как git). |
| `data/` | Общее хранилище (`files`, `projects`, `exports`) + `team_server.db`. |
| `src/` | Встроенный сайт gitingest (доступен на `/site`). |
| `run_server.py` | Точка входа сервера. |

## Возможности

### Основной сайт

- **Вход по нику** (без пароля) — при первом входе аккаунт создаётся
  автоматически с ролью Pi; роль Host выбирается в «Настройках».
- **Обзор** — статистика (проекты, участники, действия за сегодня), мои
  проекты, проекты команды, последние действия.
- **Проекты** — загрузка zip-архивом или ссылкой на git-репозиторий, поиск,
  карточки со статусами (проанализирован / PNG / digest / диаграмма).
- **Проект** — анализ, диаграмма кода (mermaid рендерится прямо в браузере),
  PNG-структура, digest, выгрузка JSON, удаление (владелец или Host).
- **Анализ репозитория** — разбор любого публичного git-репозитория по ссылке
  без сохранения в проекты (для приватных можно указать токен).
- **Журнал** — единый журнал (сайт + консоль), с поиском.
- **Команда** — пользователи и роли.
- **Cryless** — инструкция и статус сервера для библиотеки команд.
- **Настройки** — профиль, смена роли Host/Pi, выход.
- Ссылки на сайт gitingest (`/site`) и Swagger (`/site/docs`).

### Сервер

- gitingest: структура проекта, digest, статистика;
- gitdiagram-static: диаграмма архитектуры кода; если анализ не удался —
  автоматический откат на диаграмму по дереву каталогов;
- PNG-структура проекта;
- результаты анализа сохраняются и отдаются без повторного прогона.

### Консоль Host ⇄ Pi и cryless

- `upload` / `download` файлов и zip-проектов;
- `tree`, `analyze`, `render_png`, `journal`;
- `cryless create repository` / `load data` / `connection check`.

## Требования

- **Linux** (любой дистрибутив);
- **Python ≥ 3.10** и `git`;
- **Node.js + npm** — только для сборки/разработки сайта. Для запуска **не
  обязательны**: собранный сайт `web/dist` уже лежит в репозитории;
- ~250 МБ на диске.

## Установка

Одна команда — дальше скрипт всё сделает сам:

```bash
cd Team_Server-main
./setup.sh          # зависимости Python + сборка сайта (web/dist)
./setup.sh --dev    # + pytest и инструменты тестов (нужно один раз для ./run.sh test)
./setup.sh --no-web # не собирать фронтенд (использовать готовый web/dist)
```

`setup.sh` сам определяет дистрибутив и пакетный менеджер (apt, dnf, yum,
pacman, zypper, apk, xbps, emerge, eopkg, Termux pkg). Если чего-то не хватает
(Python ≥ 3.10, `python3-venv`/pip, git, Node.js/npm), скрипт **предложит
установить недостающие пакеты — с вашего подтверждения**. В систему ничего не
ставится без спроса; Python-зависимости идут в `.venv`, Node — в
`web/node_modules`. Сборка сайта идёт в `web/dist.new` и подменяет `web/dist`
только при успехе, поэтому рабочая сборка не пострадает.

## Запуск

### Хост — сервер (сайт + хост консоли)

```bash
./run.sh            # = ./run.sh server
```

Сервер слушает `0.0.0.0:8000`. Откройте в браузере:

- на этой машине — `http://localhost:8000`;
- с других устройств сети — `http://<IP-хоста>:8000`.

Отдельно запускать консоль-хост не нужно: сайт и консоль работают на одном
сервере, пишут в одну БД и одно хранилище.

### Разработка сайта (горячая перезагрузка)

```bash
./run.sh server     # в одном терминале — сервер
./run.sh dev        # в другом — Vite на http://localhost:5173 (прокси /api и /site)
```

### Pi (и Host) — консоль обмена файлами

```bash
./run.sh console --host <IP-хоста>    # на Pi
./run.sh console                      # на Host (режим выберет в меню)
```

Порт по умолчанию — `47823`. Команды: `upload` (файл или zip-проект),
`download`, `tree`, `analyze`, `journal`, `quit`. Загруженные проекты и файлы
сразу появляются на сайте Host.

### Тестовый режим: Host + Pi на одной машине

```bash
./run.sh demo                        # Host + Pi вместе, на одной машине
./run.sh demo --with-web             # и ещё проверить основной сайт по HTTP
./run.sh demo --test-isolated        # временное хранилище/БД (рабочие не трогает)
./run.sh demo --demo-dir ~/my_project  # отправить свой проект вместо образца
```

Хост-сервер поднимается в фоне, роль Pi тут же проходит полный цикл
(файл → проект → диаграмма кода → mermaid-дерево → PNG → скачивание → журнал)
и печатает отчёт с итогом `TEST MODE PASS`. Без второй машины настраивать
ничего не нужно.

### Pi — библиотека команд `cryless` (как git)

```bash
cd ~/my_project

cryless create repository my_project   # создать репозиторий (и .cryless/ в проекте)
cryless load data my_project           # загрузить файлы проекта на сервер
cryless connection check               # проверить соединение с сервером
cryless help                           # справка
```

При первом запуске укажите сервер и ник:

```bash
cryless create repository my_project --server http://<IP-хоста>:8000 --user vanya_pi
```

Условия:

- команду запускают **в корне проекта** — там, где лежат его файлы;
- в имени проекта нет пробелов и кириллицы — только латиница, цифры, `. _ -`
  (`my_project`, `api-v2`, `site.ru`).

После `create repository` появляются `.cryless/` (токен доступа, только для
владельца) и `.crylessignore` (что не отправлять; синтаксис `.gitignore`,
по умолчанию исключены `.venv/`, `__pycache__/`, `*.log`, `.env` и т. п.).
`load data` заменяет содержимое репозитория целиком (как `git push`) и сразу
запускает анализ: PNG-структура, digest и mermaid-диаграмма, а действие
попадает в общий журнал.

## JSON-API

Сайт работает через JSON-API; его же можно использовать напрямую (сессия —
cookie `nick`, как в браузере).

| Метод и путь | Назначение |
|---|---|
| `POST /api/auth/login` | вход/регистрация по нику (`{"nick": "..."}`) |
| `GET /api/auth/me` | текущий пользователь |
| `POST /api/auth/role` | смена роли (`host` / `pi`) |
| `POST /api/auth/logout` | выход |
| `GET /api/users` | пользователи и роли |
| `GET /api/stats` | сводка (проекты, участники, действия) |
| `GET /api/journal?limit=` | журнал действий |
| `GET /api/projects` | список проектов |
| `POST /api/projects` | загрузка проекта (multipart: `name`, `archive` или `source`) |
| `GET /api/projects/{id}` | проект + сохранённый анализ |
| `DELETE /api/projects/{id}` | удаление проекта (владелец или Host) |
| `POST /api/projects/{id}/analyze` | анализ: структура, digest, диаграмма, PNG |
| `GET /api/projects/{id}/diagram` | mermaid-диаграмма |
| `GET /api/projects/{id}/digest` | текстовый digest |
| `GET /api/projects/{id}/png` | PNG со структурой |
| `GET /api/projects/{id}/export` | выгрузка данных в JSON |
| `POST /api/ingest` | разобрать произвольный репозиторий по ссылке |

Служебные API: `/api/cryless/*` (для CLI `cryless`), `/site/docs` (Swagger
сайта gitingest). Неизвестные `/api/*` отвечают честным `404`.

## Роли и права

- **Host** — видит весь журнал, может анализировать и скачивать материалы
  любого проекта (PNG / digest / диаграмма / JSON);
- **Pi** — видит в журнале только свои действия, работает со своими проектами;
  чужие материалы недоступны (403).

## Переменные окружения (необязательно)

| Переменная | Назначение |
|---|---|
| `TEAM_SERVER_DB` | путь к БД (по умолчанию `data/team_server.db`) |
| `TEAM_SERVER_DATA` | каталог данных сервера (по умолчанию `data/`) |
| `GETTINGSTARTED_STORAGE` | базовый каталог хранения консоли (по умолчанию `data/`) |
| `CRYLESS_SERVER` | адрес сервера для cryless (по умолчанию `http://localhost:8000`) |
| `CRYLESS_USER` | ник пользователя для cryless |
| `CRYLESS_HOME` | каталог настроек cryless (по умолчанию `~/.config/cryless`) |

## Хранение данных

```
data/
├── files/       # файлы, отправленные через консоль
├── projects/    # распакованные проекты (<ник>__<имя>)
├── exports/     # результаты анализа: PNG, digest, диаграмма, метаданные
└── team_server.db
```

Каталог `data/` — общий для сайта, консоли и cryless, поэтому все интерфейсы
видят одни и те же проекты и журнал. Пути можно переопределить переменными
окружения (см. выше) — это используется тестами для изоляции.

## Устранение неполадок

- **Порт 8000 занят** (`[Errno 98] … адрес уже используется`) — уже запущен
  другой сервер; остановите его (`pkill -f run_server.py`) или запустите на
  другом порту.
- **Python не подходит** (`PEP 668`, системный Python слишком новый/старый) —
  всё ставится в `.venv`; используйте `.venv/bin/python`.
- **Сайт отдаёт 503 «Фронтенд не собран»** — выполните `./setup.sh`
  (или `cd web && npm install && npm run build`).
- **Приватный репозиторий не клонируется** — укажите токен в «Анализе
  репозитория» или в настройках `cryless`.
- **Диаграмма по коду пустая** — для проектов со слабыми связями система
  автоматически показывает диаграмму по дереву каталогов.
